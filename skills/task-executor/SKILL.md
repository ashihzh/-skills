# 任务执行（task-executor）

## 为什么需要它

规划技能已经把设计判断力压进了计划；执行这边的失败模式是另一种：**不看证据就宣布完成**（历史上有「声称修复实际死锁」的教训）、**同一方法头铁重试**、**顺手修范围外的东西把任务带偏**、**换个对话就把上轮没验证的结论当事实**。

本技能把这些坑变成可操作的纪律与闸门，让能力较弱的执行模型也能稳定交付到规划质量。你的记忆不在对话里，在 `ledger.md` 里。

## 铁律

1. **入口自发现，开工先读三件套**。用户说「执行一下」时**你自己去找计划，绝不向用户索要路径**；按「入口自发现」一节的顺序解析。台账是跨对话续作的唯一依据；**禁止凭对话记忆续作**。找不到任何计划 → 判定「未规划」，停下来要求补规划（见「补规划流程」）。
2. **证据判定**：没有命令输出、日志、哈希、截图或用户确认语句支撑，不许写「完成」。写结论时附出处。没验证的只能写「待验证」。
3. **红线原样遵守**：brief.md 与 plan.md 的红线章节逐条执行；发现红线与现实冲突，停下来上报，不自作主张变通。
4. **止损**：同一方法失败 2 次 → 停。换思路，或写进 ledger 阻塞项上报；不许第 3 次原样重试。
5. **范围外只登记**：计划外的新问题记进 ledger 的 backlog（附证据），不当场开修。
6. **不擅自做设计决策**：计划没覆盖的岔路走补规划流程，拍板后折进 plan.md 决策表再继续。
7. **人工闸门**：标了「人工闸门」的验收项必须等用户明确点头才标 done。机器绿 ≠ 用户满意。
8. **全程用中文，包括思维链**。推理思考（思维链）、台账、报告与用户交流一律用中文书写；代码、命令、路径、标识符保留原文。中文交付物必须配中文推理，用户才能直接审读你的思考过程。
9. **临时产物写对位置**。任何探针/调试/一次性脚本落盘前先确认路径在 `_attic/<轮>/tmp/`；写进轮目录或 `.plan` 根 = 违规，`plan-ops.sh check` 判红。
10. **证据两段式**。原始证据落 `_attic/<轮>/evidence/`，轮目录只维护几 KB 的 `evidence.md`（结论/路径/命令或哈希/时间）；别把截图/日志堆在轮目录。
11. **收工前必跑 `bash .plan/_tools/plan-ops.sh check`**，有红不得写 done；清理/归档只走该脚本（默认 dry-run），删 evidence 前先确认 `_evidence-manifest.tsv` 已落。
12. **多轮压缩是内建能力，不靠外部技能**。`.plan` 膨胀时按本技能「多轮规划压缩」一节与 task-planner 的 `references/compact-rules.md`（断链四条件）执行；`manual` 授权下未获用户明确点头，不得执行归档。

## 入口自发现（用户只说「执行一下」时你自己找）

用户不必报路径、不必贴交接提示词。按下面顺序解析，**第一步命中就停**：

1. **当前规约（首选）**：读工作区 `.plan/INDEX.md` → 取其中状态为 `active` 的那一轮目录（下文记作 `<轮>`）。
2. 读 `<轮>/ROUND.md` → 拿到 **类型 / 状态 / 下一步 / 继承自 / 本轮废弃**。
3. 读 `<轮>/plan.md`、`<轮>/brief.md`、`<轮>/ledger.md`。
   台账**只读顶部「当前状态」一屏**，历史区不要从头读。
4. **回落（旧布局）**：没有 `INDEX.md` 时，直接读 `.plan/plan.md` + `.plan/brief.md` + `.plan/ledger.md`，并按旧语义把 `.plan/` 本身当作 `<轮>`。
5. 以上都没有 → 判定「未规划」，停下来要求补规划。

**解析后必做的两件事：**
- **闸门检查**：`ROUND.md` 的「下一步」若标明某工作包「未放行 / 待用户批准」，**先问用户要不要开跑**，得到明确答复才动手。
- **不做的事**：不要读 `.agent-teams/`（运行期状态）；不要因为找不到文件就新建计划目录（那是规划技能的职责）。

**团队轮**：`<轮>/TEAM.md` 存在时，先读它拿计划↔agent-teams 映射，再用 `agent_teams_status` 对齐运行期状态；计划侧文件是唯一事实源。

## 运行模式（单任务默认，多对话可选）

- **单任务模式（默认）**：一个对话做完一个任务，主 ledger 一份到底，以下多对话纪律全部跳过。
- **多对话并行模式（可选，plan.md 声明了才进）**：你只做自己任务目录 `<轮>/tasks/<任务>/` 里的事（旧布局为 `.plan/tasks/<包>/`），只跟用户说话，不许与其他执行对话私下同步。额外纪律：
  1. 开工先登记 `LOCK: <文件列表>`，只改锁内文件；锁冲突停下来等用户仲裁。
  2. 一包一分支，不许把改动做到别的分支；主 ledger 只读索引，不写细节。
  3. 平时不许碰线上（读状态可以）；要线上验证先打预发布申请，用户批了才动，动前后各记快照。
  4. 完工交合并申请（见「收工」），缺证据项会被打回；L3 闸门只认用户亲口的可以。

## 工作循环

1. 按「入口自发现」解析出 `<轮>` → 在 `<轮>/ledger.md` 历史区追加一行「开工基线」（当前状态、哈希、服务状态等）。
2. 选下一个 pending 工作包（按序；被「待拍板决策点」卡住的包跳过并标注）。
3. ledger 标 `in_progress` → 按包内步骤执行 → 收尾跑该包验收清单。
4. **立即回写 ledger**（状态/证据/时间/备注），不许攒到最后一起记。
5. 有人工闸门 → 请用户过目 → 点头后标 done。
6. 回到第 2 步，直到全部 done。
7. 收工（见下）。

每包只验证一件事的假设组合太多时拆细：宁可包小一点，也不要一次改一堆说不清哪步起效。

## 方法论（操作要点，详单见 references/method-and-selfcheck.md）

1. **先调研后动手**：改任何东西前先读现状，把基线（哈希/行号/命令输出）记进 ledger；动过之后才能对比。
2. **一次验证一个假设**：每步动手前说清「这步验证什么、怎么算验证通过」。
3. **小步可回滚**：高风险改动前留备份点（文件 .bak.时间戳 / 复制件），每包一个回滚点。
4. **输出有界**：大文件、长日志先 grep/截取再看；不要把大段原始输出堆进对话。
5. **环境坑当场记**：踩到的坑与规避方法记进 ledger 备注，收工时可沉淀成任务副本的纪律。

## 补规划流程（计划没覆盖的岔路时）

1. 停在岔路口，把问题写清：现状、可选方案、你的推荐与理由。
2. 按规划技能的澄清清单向用户提问（一次 ≤3 个问题）。
3. 拍板结果写进 plan.md「已拍板决策表」，并在 ledger「决策变更记录」记一行，然后继续。

## 多轮规划压缩（内建能力，把历史轮 n→1 合并）

多轮接力会留下大量「已完成但还摊在 `.plan/` 根」的轮目录。直接删会丢决策；一直不压，`.plan/` 膨胀到几百 MB。本技能把「n 轮 → 1 份主题 md」做成确定流程：**四条件判定 → 用户审批 → 归档三件套 → 写合并 md → 改 INDEX**。原文永远在 `archive/<轮>/`，合并 md 只是索引，决策不丢。完整规则见 task-planner 的 `references/compact-rules.md`，合并 md 模板见 task-planner 的 `assets/TOPIC.md`。

**触发**：`.plan` 总量 > 200MB 或单轮 > 50MB 时在收工报告里提议；用户说「压缩规划」「归档 r50–r56」「清理历史轮」「把这几轮合并一下」时直接执行。

**铁律（与 planner 共用一套规则，不可放宽）**：

1. **四条候选条件全满足**（详见 task-planner `references/compact-rules.md`）：终态 / 链已断（无未归档轮继承自它）/ 同主题成组 ≥3 / 不在最近 5 轮保护窗。任一不满足 → 不压，说明原因。
2. **永不碰最近 5 轮**：按轮号降序取最大 5 个轮号，无论状态一律跳过。
3. **`manual` 授权必须先问用户**：`INDEX.md` 顶部「压缩授权」为 `manual` 时，输出候选组与断链依据后**停下来等用户明确点头**；`auto` 才按预授权直接压。
4. **先审计后动手**：第一步永远跑 `bash .plan/_tools/plan-ops.sh compact-audit`（只读）看候选报告。
5. **原文不丢**：只搬不删——各轮三件套 `mv` 到 `archive/<轮>/`，合并 md 写全必填项，细节回链 `archive/<轮>/plan.md`。
6. **一次只压一组**；多组分批，每组独立审批。

**五步流程**：

1. **审计**：`bash .plan/_tools/plan-ops.sh compact-audit` → 候选表（轮次/状态/是否被继承/是否保护窗）。
2. **选组**：按四条件复核，确定 `rNN–rMM` 一组（≥3 轮，共享主题词）。
3. **审批**：输出候选组、合并后体积、被删/被留清单；`manual` 下等用户点头，`auto` 下直接进下一步。
4. **归档**：`bash .plan/_tools/plan-ops.sh archive --rounds rNN-rMM`（先确认默认 dry-run 输出无误；evidence 删除前 manifest 已落）。
5. **写合并 md + 改 INDEX**：按 `assets/TOPIC.md` 写 `archive/topics/<主题>-rNN-rMM.md`（必写项见模板）；`INDEX.md`「已压缩组」表加一行，被压各轮状态改 `archived` 或移入历史表；收尾跑 `plan-ops.sh check` 零红才算完成。

**边界**：只操作 `.plan/` 内轮目录/archive/INDEX；不动业务代码、不改技能母版、不 push、不产 commit；`_attic` 永不自动删、本流程不碰它。

## 质量自检闸门（每包收尾逐条过）

- [ ] 本包验收清单逐条有证据
- [ ] ledger 已回写（状态/证据/时间）
- [ ] 红线零违反
- [ ] 没把推测写成「完成」
- [ ] 范围外发现进 backlog，没有顺手开修
- [ ] 人工闸门项等到了用户点头
- [ ] 若触发了多轮压缩：四条件逐条核对未放宽、最近 5 轮未参与、manual 已获用户明确同意、三件套已 mv 到 archive、合并 md 必写项齐全含回链、INDEX 已压缩组已更新、check 零红

## 跨对话 / 跨任务续作

- 换对话：新执行者按「入口自发现」读三件套即可续作，**不依赖旧对话上下文，也不需要用户贴交接提示词**。
- 多任务并行：各任务工作区各有 `.plan/`，台账各记各的；不要把 A 任务的状态写进 B 任务。
- 同工作区多对话并行：一任务一分支一任务级台账（`<轮>/tasks/<任务>/`，旧布局 `.plan/tasks/<包>/`），主 ledger 只记索引；动手前登记文件锁；合流顺序听 plan.md，锁冲突听用户仲裁。
- 任务级定制遵循 `<轮>/skills/` 下的任务副本（副本优先，缺章节回落全局母版）。有副本时副本优先；**没有副本就按本母版自动解析**，不要因为缺副本就停下。

## 收工

1. 对照 plan.md「完成判定」逐条核对，全过才算完成。
2. **先跑 `bash .plan/_tools/plan-ops.sh check`，零红才可收工**；有红先按红线处置（归置临时产物/补 evidence.md/补 INDEX 压缩授权行），不得带红写 done。
   - 体积闸门：若 `du -sh .plan` > 200MB 或单轮 > 50MB，**向用户提议压缩**（说明候选组与断链依据），由本技能按「多轮规划压缩」一节自行执行；manual 授权下必须等用户点头，不自动压。
3. ledger 收尾：全部 done / 明确标注 blocked，登记时间与证据。
4. brief.md 有「项目回写条款」的（如回写某进度文件），照办。
5. 需要跨项目/换机器/换人长距离移交时，才用 session-handoff-prompt 生成交接提示词；**同一工作区持续推进不需要，用户也不必贴它**。轮内如需保留，放 `<轮>/handoff.md`，并标注「导出物，不得作为事实源」。
6. 多对话模式完工交合并申请（缺一不可）：①改了什么（分支名 + diff stat）；②L0 门禁证据；③L1 功能证据；④L2 回归证据；⑤回滚点（备份位置+哈希）；⑥LOCK 释放声明。最后只问用户一句：「这样可以吗？」

## 边界

- 与 task-planner：规划产出计划、执行消费计划；设计问题回收给规划流程（补规划），不在执行侧拍板。**多轮压缩共用规划侧持有的 `references/compact-rules.md` 与 `assets/TOPIC.md`——规划侧声明授权、执行侧落地，不引入第三个技能。**
- 与 session-handoff-prompt：ledger 已承担任务内跨对话状态；交接提示词只用于换项目/换环境的长距离移交。
