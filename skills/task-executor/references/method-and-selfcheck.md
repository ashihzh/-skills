# 方法论详单 + 通用自检清单

## 1. 先调研后动手

- 动手前：读目标文件/配置/服务现状；记基线进 ledger（哈希、行号、状态、命令输出摘要）。
- 为什么：没有基线就无法证明「改了之后变好了」，也无法回滚；「文档说修好了」不等于现实，关键项现场复核。
- 产出格式：ledger 开工基线一节，每行「项 / 现状 / 证据」。

## 2. 一次验证一个假设

- 每步动手前先写：「这步验证什么假设、怎么算通过」。
- 一次改多个变量 → 无法归因，等于白干；宁可多几步小改。

## 3. 证据判定

「完成」的证据类型（至少一条）：

- 命令输出（贴关键行，注明出处）；
- 哈希/字节数对比（改动前后）；
- 测试/验收脚本结果（贴失败项明细，不只贴总分）；
- 截图或用户确认语句（人工闸门项）。

反例（禁止）：「应该没问题」「看起来好了」「之前测过」。

## 4. 止损

- 同一方法失败 2 次 → 强制停手。可选：换思路 / 查日志定位 / 写进 ledger 阻塞项上报。
- 失败 2 次还想原样重试第 3 次 = 头铁，这是流程禁止的，不是风格问题。

## 5. 小步可回滚

- 高风险改动前备份（.bak.时间戳 / 复制件），回滚方式写明。
- 每个工作包一个回滚点；包内大步骤也可中间留点。

## 6. 输出有界

- 读大文件/长日志：先 grep 关键词、截取关键段，再决定要不要展开。
- 不把整文件、整日志倒进对话；只带回下一个决策真正需要的行。

## 7. 环境坑记录

- 踩坑当场记进 ledger 备注：现象、根因、规避方法。
- 收工时判断是否值得沉淀进任务副本的纪律章节。

## 8. 多对话并行安全（多对话模式才看）

- 一包一分支，改动不出分支；主 ledger 只读索引，细节写包 ledger。
- 动线上（部署/重启/写远端）默认禁止；用户批准的预发布也要前后快照（状态+哈希）进 ledger。
- 验收脚本会动服务的（如 stop/start），绝不与其他对话并发跑；跑之前确认锁在谁手里。
- 合并申请六件套不齐不许提；被打回「改」不算失败，按意见补证据再提。

## 通用自检清单（每工作包收尾逐条过）

- [ ] 本包验收清单逐条有证据
- [ ] ledger 已回写（状态/证据/时间）
- [ ] 红线零违反（brief + plan 两处对照）
- [ ] 没把推测写成「完成」
- [ ] 范围外发现进 backlog，没有顺手开修
- [ ] 人工闸门项等到了用户点头
- [ ] 回滚点存在且可用（高风险包必查）
