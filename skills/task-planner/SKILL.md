# 任务规划（task-planner）

## 为什么需要它

任务做烂，多数不是执行时手抖，而是开工前没人把它想透：痛点没问清就动手、取舍没拍板就堆料、验收没有口径，最后「机器全绿但用户不满意」。

本技能把「想清楚」本身变成可交付物：强模型把设计判断力**压进计划文本**，压到「决策完整」——执行模型拿着计划不需要做任何设计决策，就能干到同等效果。产出不是聊天里的一段话，而是任务工作区里的三件套：`plan.md`（计划）+ `brief.md`（说明书/事实/红线）+ `ledger.md`（任务台账）。

## 铁律

1. **规划阶段只读、零副作用**。只读文件、查状态、看日志；不改文件、不动服务、不部署。想动手的冲动全部留给 task-executor。
2. **复杂任务强制先澄清再规划**。痛点、边界、取舍、验收口径没拍板之前不出计划。提问清单与「什么算复杂」见 `references/clarify-checklist.md`。一两步能说清、无取舍的小任务可以跳过提问，但决策必须写进「默认假设（可推翻）」。
3. **决策完整（decision-complete）**。每个工作包执行模型都不需要做设计决策：要么已拍板进「已拍板决策表」，要么显式列为「待拍板决策点」并附推荐选项。执行中冒出的设计岔路属于规划失职，由 task-executor 走补规划流程回收。
4. **事实带证据，假设要标注**。已确认事实附命令输出/哈希/行号出处；没验证的写成「默认假设（可推翻）」或「待验证」。历史记录会过期，关键项现场复核——被推翻的旧结论保留原文并标注，不抹掉。
5. **验收口径可判定**。量化指标（给数字）与主观闸门（用户明确说「可以」才算过）并存。效果类任务只留「脚本全绿」当验收等于没有验收。
6. **母版零任务内容**。任务具体内容只进该任务的 `.plan/`；本技能文件永远通用。这是「多任务不互相污染」的前提。
7. **必写 `INDEX.md` 入口与压缩授权**。每轮规划收尾时更新 `.plan/INDEX.md`：`当前生效轮` 一行 + 轮次表一行，并在顶部写 **`压缩授权: manual | auto`** 一行（改一次永久生效；`manual` 时每次压缩前必须问用户）。
   这是规划与执行的**唯一绑定点**——不写它，执行技能就找不到计划，用户就被迫手写路径口令。
   布局契约见本技能目录下的 `references/plan-layout.md`，照它写即可。
8. **全程用中文，包括思维链**。推理思考（思维链）、计划、台账、报告与用户交流一律用中文书写；代码、命令、路径、标识符保留原文。中文交付物必须配中文推理，用户才能直接审读你的思考过程。
9. **临时产物默认落 `_attic/<轮>/tmp/`**。规划阶段虽零副作用，但计划里必须为执行阶段写明垃圾去处：探针/调试/一次性产物直接写 `_attic/<轮>/tmp/`，不写轮目录或 `.plan` 根。
10. **证据两段式**。原始证据落 `_attic/<轮>/evidence/`，轮目录内只维护一份几 KB 的 `evidence.md`（一行一条：结论/路径/命令或哈希/时间）；禁止把大证据堆在轮目录。
11. **规划要预留压缩义务**。压缩是本套技能的内建能力，不靠任何外部技能：规划侧负责声明 `INDEX.md` 的「压缩授权」开关并把断链压缩规则写进计划，执行侧（task-executor）按同一套规则真正执行。规划时若发现 `.plan>200MB` 或单轮>50MB，把「提议压缩」写进计划，但不擅自压缩（执行者只提议、不自动压）。断链压缩四条件与执行顺序见 `references/compact-rules.md`，合并 md 模板见 `assets/TOPIC.md`。
12. **状态词用唯一权威 `references/state-machine.md`**。轮次/任务状态全集（含合法与非法迁移、每态进出条件）只在该文件定义；`assets/ROUND.md` / `assets/TASK.md` / `references/plan-layout.md` / `task-executor/assets/ledger-template.md` 只引用、不重复列全表。新状态先改该文件，再决定哪些层级暴露子集。
13. **反模式库 `references/anti-patterns.md`**。反复踩的坑抽象成通用反模式（现象/根因/规避/检测信号），澄清与风险登记时参考它预判坑点；本文件永不含具体轮号/slug/commit/token（母版零任务内容）。

## 运行模式（单任务默认，多对话可选）

- **单任务模式（默认）**：一个对话做完一个任务，三件套一份到底，以下多对话章节全部跳过，零负担。
- **多对话并行模式（可选）**：多个对话各领一个大工作包同时开工。启用时必须在 plan.md 声明，并配齐：包级独立台账（随分支走，主 ledger 只记索引）、文件占锁规则、分支与合流顺序、分级完成定义 DoD、发布与部署权（谁能动线上、一次发一个）。详见 plan-template.md 标有「多对话」的小节；澄清阶段按 clarify-checklist.md 的 H6 确认是否启用。
- 判断标准：用户说「同时开几个」「并行」「一人公司」「多对话」即启用；没说就默认单任务，不追问。

## 工作流

### 第 1 步：只读侦察

- 采集：需求现状与历史实现（含缺陷）、环境与部署事实、既有约束、历史决策/进度文件。
- 关键项现场复核再写入；复核前确认没有别的任务正在并发改动同一目标。
- 侦察产出直接进 `brief.md` 的事实表，每行带证据列。

### 第 2 步：澄清拍板（复杂任务强制）

- 按 `references/clarify-checklist.md` 提问；一轮不超过 5 个问题，问完消化再问下一轮。
- 含糊答案（「都行」「1 或 3」）必须追问；用户的自由补充往往才是真需求，逐条吸收进决策表。
- 拍板结果整理成「已拍板决策表」，这是计划的需求说明书；每条决策标注「来源」（用户拍板/代拍板/文档推定）。
- **意图层**：把用户明确说过的关键原话（含消息引用/时间）原样记入 brief.md 的「用户原话决策」区，标注其为最高优先级。书面结论与该区原话冲突时以原话为准。

### 第 3 步：写 plan.md

- 按 `assets/plan-template.md` 写，小节一个不能少。
- 工作包按风险低→高排序，每个写全：目标 / 改哪些文件 / 步骤 / 验收 / 风险与回滚。
- **决策完整自检**：逐包问「执行模型会在这里被迫做设计决策吗？」会 → 回到第 2 步补拍板，或列「待拍板决策点」并注明未拍板不得开工该包。

### 第 4 步：写 brief.md

- 按 `assets/brief-template.md`：事实表（带证据）、硬约束红线、明确不做的事、交付物清单。
- 项目回写条款（如收工必须回写某进度文件）写这里，执行技能会照办。

### 第 5 步：初始化任务实例

布局契约见本技能目录下的 `references/plan-layout.md`（应先读它）。轮次卡片、任务卡片、团队映射模板见 `assets/ROUND.md`、`assets/TASK.md`、`assets/TEAM.md`。最小形态：

```
<workspace>/.plan/
  INDEX.md                  ← 必须写：当前生效轮 + 轮次表 + 压缩授权 manual|auto
  _attic/                   ← 垃圾区（永不自动删）：<轮>/{evidence,tmp}/、_root-tmp/、skill-backup/
  _tools/                   ← 唯一合法的清理/审计工具 plan-ops.sh（默认 dry-run）
  archive/                  ← 历史轮三件套 archive/<轮>/、压缩合并 md archive/topics/
  <轮>/                     ← 一轮一个目录，命名 rN-<slug>，N 递增永不复用
    ROUND.md                ← 类型/状态/继承自/本轮废弃/目标/验收/下一步
    plan.md brief.md ledger.md
    evidence.md             ← 几 KB 证据索引（原始证据在 _attic/<轮>/evidence/）
    skills/                 ← 可选：任务级技能副本（副本优先，缺章节回落母版）
    tasks/<任务>/           ← 仅多任务轮/团队轮
    TEAM.md                 ← 仅团队轮
```

> 轮目录里**只允许** `ROUND.md`+三件套+`evidence.md`（+可选 skills/tasks/TEAM）；出现 `_*`/`*.png`/`*.mjs`/`*.py` 或 `evidence/` 目录即违规，`plan-ops.sh check` 判红。

- ledger 按双区制建：顶部「当前状态」覆盖式、永远一屏；下方历史只追加不改写。
- **轮类型决定内部结构**：单任务轮把工作包写进 `plan.md`，**不建 `tasks/`**（不为对称硬造空目录）；
  多任务轮建 `tasks/<任务>/TASK.md`，轮级三件套作「总」；团队轮再加 `TEAM.md`。
- **新轮必须写「继承自」和「本轮废弃」**：显式声明上一轮哪些结论作废，这是消灭「新旧计划互相矛盾」的关键。
- **`INDEX.md` 是规划与执行的唯一绑定点**：写完三件套立刻更新它，否则执行技能找不到计划。
- 多对话模式：一任务一分支一任务级台账（`<轮>/tasks/<任务>/`），主 ledger 只记索引行；列出合流顺序。
- 任务级定制（项目专有纪律、术语、事实）写进副本或 brief.md；副本规则：**副本优先，缺章节回落母版**。绝不写回全局母版。
- 若任务工作区采用 `.agents/skills/` 技能目录惯例，副本也可放那里获得原生触发。

### 第 6 步：交付

- 给出文件路径 ＋ 三句以内「这轮真正定了什么」＋ 一句开工指令。
- **开工指令只写「执行一下」**：`INDEX.md` 已就位，执行技能会自发现，不要教用户手写路径口令。
  仅当本轮是团队轮时，补一句「用 TEAM.md 建 agent-teams 等我批准」。
- 不在对话里复述计划全文；计划以文件为准。

## 计划质量标准

好计划的判据是「换一个没见过本对话的执行模型，也能不出错地干完」：

1. 自包含：执行模型看不到原对话，计划自带背景、事实、路径、命令。
2. 决策完整：无隐含设计判断。
3. 验收可判定：每包有证据要求，全局有完成判定。
4. 风险有回滚：高风险包写明备份点与回滚方式。
5. 假设显式化：默认假设集中一节，动手前可逐条确认。

## 边界

| | task-planner | task-executor | session-handoff-prompt |
|---|---|---|---|
| 干什么 | 想清楚并写成计划三件套；声明压缩授权、持有断链压缩规则 | 照计划执行并回写台账；按同一套规则真正执行压缩 | 换对话/换环境的项目进度移交 |
| 状态载体 | 生成 `.plan/` 三件套 | 持续回写 ledger.md | 一次性交接提示词文件 |
| 任务内容 | 只进 brief/plan/副本 | 只进 ledger/副本 | 项目事实放任务级配置，母版只留模板 |
| 多轮压缩 | 声明授权开关 + 把压缩义务写进计划 + 持有规则/模板 | 阈值提议 + 按四条件执行归档/合并 md/改 INDEX | 不涉及 |

**多轮压缩能力内置于本套技能**：断链压缩四条件、执行顺序、合并 md 必写项在 `references/compact-rules.md`，空模板在 `assets/TOPIC.md`。规划侧（本技能）负责声明授权与预留义务，执行侧（task-executor）按同一套规则落地——两者共用一份规则，不引入第三个技能。

已有 `.plan/` 台账在持续推进时不需要再生成交接提示词；跨项目长距离移交才两者并用。执行中遇到设计岔路，由 task-executor 按本技能第 2 步的澄清流程补拍板。

## 自查清单（交付前逐条过）

1. 全程只读、零副作用。
2. 复杂任务澄清过了；跳过澄清的决策进了「默认假设」。
3. plan.md 模板小节一个不缺。
4. 逐包过了决策完整自检。
5. 事实有证据出处，推测没有混进「已确认」。
6. 验收口径量化 ＋ 主观闸门并存。
7. 三件套就位、ledger 全 pending；多对话模式才另建包级三件套副本，单任务轮不建副本。
8. 技能母版文件里没有出现本任务的具体内容。
9. `INDEX.md` 顶部有「压缩授权」行；轮目录无临时产物/原始 evidence（已归 `_attic/<轮>/`）；压缩义务已写进计划。
10. 多轮压缩规则就位：`references/compact-rules.md`（四条件+执行顺序+必写项）与 `assets/TOPIC.md`（合并 md 模板）在本技能目录内，不引用任何外部技能。
11. 状态词只在 `references/state-machine.md` 定义，模板/文档/INDEX 均无重复全量词表（层级子集已标注「本层级子集，全集见 state-machine.md」）。
